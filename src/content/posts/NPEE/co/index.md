## 前言

关于计组、操作系统和计网，我认为学习方法和数据结构有差别。

### 计算机系统层次结构

这个考点比较绕，主要可以从下面走：

首先是层次问题，高级程序语言 - 汇编语言 - 操作系统 - 机器级语言 - 微程序控制器

可以从这个方向记忆，也就是谁为谁提供了服务，也可以这么记，操作系统是最靠近硬件的一层软件。

还需要辨析编译、汇编、翻译、链接的区别。

编译指的是一次性把高级语言转换成汇编语言或者机器级语言，汇编指的是把汇编语言转换成机器级语言，翻译指的是把高级语言逐条翻译为机器级语言（不生成目标文件），链接指的是把多个目标文件连接成一个可执行文件，是操作系统那块的概念。

此外，还有 ISA。ISA 是指令体系结构，相同的 ISA 可以对应不通的机器实现，可以通过 x86 体系结构经过非常多代硬件迭代，但是 ISA 可能不变。

### 存储程序的执行流

这块放在 CPU 那一章细讲，主要是理解一控制驱动和数据驱动。控制驱动指的是按照指令顺序执行，而数据驱动指的是一来数据就计算。

### 性能指标

主要是记忆性的东西，其实考的非常杂。主要是要记住 CPI 是什么，IPS 是什么之类的以及其中的转换关系。

例如 CPI 是 CPU 执行一条指令所需要的时钟周期数，主频是 CPU 一秒有多少个时钟周期。

所以，计算一条指令的运行时间，先计算一个时钟周期是多少，也就是 1/主频，然后再用 CPI 乘以这个时钟周期，就是一条指令的运行时间。

对于这个考点，需要注意题目描述，题目里有时候描述是执行 x 条指令，有时候的描述是执行 y 个时钟周期。

此外还可以注意，A 的主频高，B 的主频低，不意味着某程序在 A 上运行时间一定比在 B 上运行时间短。

做这类题可以设置一个 N，意思是总指令数。

### 字，字节，字长，位

什么是位，什么是字节，什么是字，什么是字长？

位是最小的单位，一个二进制位只能表示 0 或 1。

字节是 8 位，一个字节可以表示 0 - 255。字节是存储的基本单位。

而什么是字，什么是字长，需要根据计算机本身的系统结构来确定。

例如对于古早的机器，可以用 2 字节表示一个字，即 16 位，那么字长就是 16 位。而此时，机器的编址就是按字编址，而不是按字节编址。

然而现代计算机都是按字节编址的，1 字就是 1 字节，即 8 位。

### 数制和编码

这个考点说难也难，说简单也简单，主要是细节问题。

2 进制、8 进制、10 进制、16 进制的相互转换。

对于 10 进制转 2 进制整数部分，可以采用短除法，也就是除以 2，取余数，直到商为 0 为止，然后从下到上把余数拼接起来。

对于 10 进制转 2 进制小数部分，可以采用乘以 2，取整数部分，直到小数部分为 0 为止，然后从上到下把整数部分拼接起来。

当然熟练后更快的做法是拼凑，也就是利用 2^x 次方的加法转换为对应的 2 进制数。

这里可以注意，不是所有的 10 进制数都可以精确的转换为 2 进制数，例如 0.1，转换为 2 进制数会是一个无限循环小数。

对于 2 进制转 10 进制，可以采用按权展开法，也就是把 2 进制数按权展开，然后相加。

对于 8 进制转 2 进制，可以采用拆分法，也就是把 8 进制数拆分为 2 进制数，每 3 位拆分为 1 位。

对于 2 进制转 8 进制，可以采用合并法，也就是把 2 进制数合并为 8 进制数，每 3 位合并为 1 位。

对于 16 进制转 2 进制，可以采用拆分法，也就是把 16 进制数拆分为 2 进制数，每 4 位拆分为 1 位。

对于 2 进制转 16 进制，可以采用合并法，也就是把 2 进制数合并为 16 进制数，每 4 位合并为 1 位。

还可以注意表示，二进制数可以表示为 B 的形式，八进制数可以表示为 O 的形式，十六进制数可以表示为 H 的形式。

例如 $1010_2 = 1010B$，$13_8 = 13O$，$15_{16} = 15H$。

### 真值，机器数，无符号数与有符号数，编码

真值指的是机器数对应的实际值，例如 $1010_2 = -2_{10}$。

机器数指的是计算机中实际存储的值，一般都是以二进制的方式存储。

需要注意的是，无论对于何种编码，计算机的存储都是相同的，只是 **解释方式** 发生了改变。

在讨论编码之前，需要捋清楚无符号数和有符号数的区别。

#### 无符号数与有符号数

无符号数指的是机器数中表示的数没有负数，即只有正数，所有的位都是用来表示数值的，不需要考虑符号位。

例如 8 位无符号数可以表示的范围为 0 - 255，即 $00000000_2 - 11111111_2$。

而有符号数的第一位一定是符号位，0 表示正数，1 表示负数。需要注意的是，原码、反码、补码、移码都是基于 **有符号数** 去讨论的，所以即便原码看着和无符号数很像，但是其本质是不一样的。

#### 原码

原码的第一位是符号位，0 表示正数，1 表示负数，后续的位数表示数值的绝对值。

例如对于 15 和 -15，其 8 位原码分别为 $00001111_2$ 和 $10001111_2$。

对于 8 位原码，其表示范围为 -127 - 127，即 $11111111_2 - 01111111_2$。

从而产生了一个问题，即 0 的表示是不唯一的，即 $00000000_2$ 和 $10000000_2$ 都表示 0。

原码很直观，但是这里先不讲为什么原码的计算很不方便。

由于原码的计算很不方便，所以很少在计算机中被使用到（但是也有应用场景，例如 IEEE 浮点数的阶码部分的计算）

#### 反码

反码的第一位是符号位，0 表示正数，1 表示负数，后续的位数是数值的绝对值的反码。

这里先不讨论反码的来源，先说反码的计算方法。

对于正数，其反码和原码相同，因为正数的反码就是其本身。

对于负数，其反码是原码除了符号位的每一位取反，即 0 变 1，1 变 0。

例如对于 15 和 -15，其 8 位反码分别为 $00001111_2$ 和 $11110000_2$。

对于 8 位反码，其表示范围为 -127 - 127，即 $11111111_2 - 01111111_2$。

从而也有一个问题，即 0 的表示是不唯一的，即 $00000000_2$ 和 $11111111_2$ 都表示 0。

反码在计算机中几乎没有任何应用，只是补码的过渡态。

#### 加法器、补数与补码的来源

加法器是计算机中用于执行二进制加法运算的核心逻辑电路，主要包括半加器、全加器以及多位并行加法器。

半加器只负责计算本位两个一位二进制数的加法，不考虑来自低位的进位。

输入：被加数 A，加数 B
输出：本位和 S，向高位的进位 C
逻辑表达式： S = A ⊕ B（异或运算） C = A · B（与运算）
示例：计算 1 + 1 时，S = 1 ⊕ 1 = 0，C = 1 · 1 = 1，合起来输出二进制 10。 注意：半加器因为无法接收低位产生的进位输入，所以不能直接用于多位数的进位加法。
二、全加器（Full Adder）
全加器在半加器的基础上，增加了接收低位进位的功能。

输入：被加数 A，加数 B，来自低位的进位 C_in
输出：本位和 S，向高位的进位 C_out
逻辑表达式： S = A ⊕ B ⊕ C_in C_out = (A · B) + (C_in · (A ⊕ B))，也可以写成 (A · B) + (A · C_in) + (B · C_in)
示例：计算 1 + 1 + 1（包含低位进位 1）时，S = 1，C_out = 1，合起来输出二进制 11。
三、并行加法器（Parallel Adder）
为了实现多位二进制数的快速相加，通常将多个全加器组合起来使用：

串行进位加法器：将多个全加器首尾相连，进位像水流一样从低位向高位逐级传递，延迟较高。
超前进位加法器（先行进位）：通过进位生成的布尔代数逻辑，提前同时计算出每一位的进位信号，不必等待低位逐级传递，速度极快。 实际工程中，常以 4 位全加器作为一个基本模块组装并行计算，并在模块间通过进位链进行级联。

在这里讲加法器，是因为可以理解补码的来源。

暂时不考虑溢出的情况，仅考虑下面的情况。

对于 8 位无符号数，13 和 12 的二进制表示分别为 $00001101_2$ 和 $00001100_2$，相加可得 $00011001_2$，转换为十进制为 25。

然而，对于 8 位无符号数，13 - 12，转换为二进制为 $00001101_2 - 00001100_2$，相减可得 $00000001_2$，转换为十进制为 1。

对于 8 位原码 13 + 12，转换为原码为 $00001101_2 + 00001100_2$，相加可得 $00011001_2$，转换为十进制为 25。

然而，对于 8 位原码 13 - 12，转换为原码为 $00001101_2 - 00001100_2$，相减可得 $00000001_2$，转换为十进制为 1。

这看起来对人类而言很直观，但是对于计算机来说，相减如何实现？

若要让无符号数或者原码做减法，计算机必须先比较两个数的绝对值大小，用绝对值大的减去绝对值小的，单独确定符号位。

最后最重要的，额外设计一套极其复杂的减法器硬件电路。

硬件资源是稀缺的，所以需要一种更简单的方法来实现减法。

补数指的是对于一个无符号数 x，对其模 n，那么 x 的补数就是 n - x。

对于 8 位无符号数 12，其模为 256，所以 13 的补数为 256 - 12 = 243。

考虑硬件情况，假设要计算无符号数 13 - 12，那么等同于计算 13 + 256 - 12 = 13 + 244 = 257。考虑二进制的情况，13 - 12 等同于 13 + 244 即 $00001101_2 + 11110100_2 = 00000001_2$，最高进位因为位数只有 8 位被天然地舍弃，即自动 -256，或者说模 256，所以结果为 1。

这个 243 是如何计算的？就是 12 的补数，即对无符号数而言，就是全部按位取反然后 + 1。

所以可以得出下面的结论：

计算机的寄存器位数是固定的。对于 8 位二进制系统，其模为 $2^8 = 256$。

当数值达到或超过 256 时，最高进位会自动丢弃（溢出舍弃），相当于时钟走满一圈归零。

在模 256 的系统中，减去一个数相当于加上这个数的补数。

例如 $13 - 12 \equiv 13 + (256 - 12) \pmod{256}$

那么对于有符号数呢？

考虑原码 13 - 12，原码为 $00001101_2 - 00001100_2$，如果采用和无符号数补数求法类似的思路，能不能得到正确的结果？

#### 补码

补码的第一位是符号位，0 表示正数，1 表示负数。对于正数，其补码和原码相同。对于负数，其补码是原码除了符号位的每一位取反然后 + 1。

对于 8 位补码，其表示范围为 -128 - 127，即 $10000000_2 - 01111111_2$，没有正 128 这个数，且没有多余的 0。

例如 -12 的原码为 $10001100_2$，其补码为 $11110100_2$。

13 - 12 等同于 13 + [-12]补，即 $00001101_2 + 11110100_2 = 00000001_2$，最高进位因为位数只有 8 位，最高位被天然地舍弃。

对于补码，可以这么理解，第一位（即符号位）理解为负位权，对于 8 位补码，即 $-2^7$，所以 -12 的补码就可以理解为 -2^7 + 2^6 + 2^5 + 2^4 + 2^2 = -12。

#### 移码

移码即相对于补码偏移 x 位（x 默认是 2^n），即对于 8 位移码，即相对于补码偏移 128 位。

对于 -128，其补码为 $10000000_2$，其移码为 $00000000_2$。

对于 0，其补码为 $00000000_2$，其移码为 $10000000_2$。

默认的移码表现形式为相较于补码，符号位直接取反。

移码在计算机中的应用主要是用来表示浮点数的阶码，但需要注意，浮点数的阶码的移码偏移量是 127，而不是 128。

#### C 语言整数类型及转换

C 语言主要有以下几种整数类型：

char：1 字节，8 位；

short：2 字节，16 位；

int：4 字节，32 位；

**long：4 字节，32 位**；这个需要尤其注意，在考研范围里，long 是 32 位。

long long：8 字节，64 位；

对于整数类型和转换，需要注意：

如果是长转短，那么高位直接截断，只保留低位。

如果是短转长，那么高位得根据是无符号数还是有符号数来决定，无符号数高位补 0，有符号数高位补符号位。

```c
unsigned short a = 65530;
int b = a;
```

分析可知，对于无符号数 a 而言，其二进制为 FFFF FFFAH，第二步发现是 int 是 32 位，所以首先进行扩展。由于无符号数的扩展是直接补 0，所以扩展为 0000 0000 FFFF FFFAH，然后再解释为 int 型，也就是 65530。

```c
short a = -1;
unsigned int b = a;
```

分析可知，对于短整型 a，其二进制为 FFFF FFFFH，第二部发现 unsigned int 是 32 位，所以首先进行扩展。由于有符号数的扩展是根据符号位来决定，所以扩展为 FFFF FFFF FFFF FFFFH，然后再解释为 unsigned int 型，也就是 2^32 - 1。

### 基本的计算

#### 移位运算

移位运算分为逻辑移位和算术移位。

逻辑移位是直接将二进制位向左或向右移动，移动后空位补 0。

算术移位是根据符号位来决定，如果是正数，则补 0，如果是负数，则补 1。

例如对于 8 位补码 1010 1010，逻辑左移一位后为 0101 0100，算术左移一位后为 0101 0100，逻辑右移一位后为 0101 0100，算术右移一位后为 1101 0100。

由于二进制的表达，移位运算天然地和乘除法有关系。

算数左移相当于乘以 2，算数右移相当于除以 2。

例如 8 位补码 1100 1010，其真值为 -54，算数左移一位后为 1001 0100，其真值为 -108，算数右移一位后为 1110 0101，其真值为 -27。

需要注意的是，如果符号位发生了改变，那么一定发生了溢出。例如对于 8 位补码 1000 0000，其真值为 -128，算数左移一位后为 0000 0000，其真值为 0，发生了溢出。

#### 对加法器的补充

对于加法器而言，如果要实现减法，那么一定是先按位取反然后 + 1，这个 + 1 是另外的信号控制输入，所以对于加法器本身而言，计算 a - b，实质上是计算 a + [-b]反 + 1，而不是 a + [-b]补。

所以说反码实质上是加法器的一种状态而已。

#### 补码加减法运算

本质上，补码加减法运算就是将减法转换为加法。

也就是 [A + B]补 = [A]补 + [B]补（mod 2^(n+1)），[A - B]补 = [A]补 + [-B]补（mod 2^(n+1)）。

#### 判定溢出与标志位

判断溢出有 3 种方式，可以采用 1 位符号位，显然只有正数 + 正数和负数 + 负数的形式有可能发生溢出，所以当符号位发生改变时，则发生了溢出。

第二种方法是采用 1 位符号位并且结合进位来判断，当最高位的进位和符号位的进位不同时，则发生了溢出。

第三种方法是采用双符号位，即 00 表示正数，11 表示负数，01 表示正数溢出，10 表示负数溢出。

需要注意的是，如果采用双符号位，在存储的时候仍然只存 1 位（因为只有计算的时候需要扩展为 2 位符号位，一个具体的数不可能是 01 态）

4 个标志位

- OF：Over Flag，代表有符号数运算是否发生溢出。
- SF：Sign Flag，代表运算结果的符号位。
- ZF：Zero Flag，代表运算结果是否为 0。
- CF：Carry Flag，代表无符号数运算是否发生了溢出
  - 硬件计算逻辑：$\text{CF} = C_{\text{out}} \oplus \text{Sub}$（其中 $C_{\text{out}}$ 为加法器最高有效位的进位输出，$\text{Sub}$ 为减法控制信号：加法为 0，减法为 1）。
  - 加法运算（$A + B$）：$\text{CF} = C_{\text{out}}$。若最高位产生进位，则 $\text{CF} = 1$，表示无符号数加法溢出。
  - 减法运算（$A - B$）：$\text{CF} = \overline{C_{\text{out}}}$（进位取反表示借位）。若运算需要借位（即 $A < B$），则 $\text{CF} = 1$，表示无符号数减法产生借位。

需要注意的是，对于无符号数的加减法而言，OF 是没有意义的，但是需要按照有符号数的解释方式来计算 OF 标志位。

对于有符号数的加减法类似，CF 是没有意义的，但是需要按照无符号数的解释方式来计算 CF 标志位。
