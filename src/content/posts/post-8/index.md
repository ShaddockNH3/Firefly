## 前言

此前已经写过一篇树莓派 5 刷 debian13，使用 waydroid + 修改底层模块兼容 ALAS 的方法。

你可以访问 [此处](https://blog.attilio.cc/posts/post-4/) 来获得这篇过时的教程，密码为：2004122120070130。

然而该方法过于低效，以侵蚀一过图速度为例，在 PC 模拟器上需要 5s 左右的时间，而在该方案下需要 10s 的时间。

为了充分发挥树莓派的性能，考虑使用 Android 系统作为宿主机，通过局域网 PC 部署 ALAS 实施自动化控制。

该方案侵蚀一过图速度为 3s 附近，极大提高了效率。

## 刷安卓系统

刷的系统是 AOSP，在给足权限后（例如网络 ADB）后，需要注意将默认网络可通性检查指向国内网络。

## 安装碧蓝航线

使用树莓派访问碧蓝航线官网，正常下载 apk 即可。

## ADB 连接

由于树莓派对电压的要求较为苛刻，必须是 5V 5A 的输出。所以如果电脑没有这个口供电，采用网络 ADB 即可。

## 通过路由器得到局域网 IP

访问路由器，得到树莓派的局域网 IP，将该 IP:5555 填入 ALAS 中即可。

## 手动干预

### 使用 scrcpy 控制

[scrcpy](https://github.com/genymobile/scrcpy) 是一个强大的安卓控制软件，可以通过下面的命令访问树莓派：

```powershell
./adb connect IP:5555 # 需要替换为实际 IP
./scrcpy 
```

需要注意，如果有多个 ADB 连接，那么可以使用以下命令获取被分配的机器序号：

```powershel
./adb devices
```

然后指定该机器码访问即可。

然而，scrcpy 对树莓派性能消耗极为巨大，主要是因为画面传输。

因此可以采用下面的方案。

### 使用采集卡访问画面

购买一块采集卡，通过 mini hdmi 线接到树莓派上。

本想修改 ALAS 程序让其可以通过采集卡控制，然而由于色差问题，需要自己写程序进行色差修正，且不具备普适性，因此放弃基于采集卡提取画面，仅仅使用其访问。

可以采用 potplayer / obs 的方式访问采集卡画面，但无法控制。

事实上只需要简单修改 scrcpy 控制，让其不传输画面即可。

```powershell
.\scrcpy --no-video --no-audio --mouse=uhid 
```

至此可以手动干预游戏。

## 缺点

目前已知的缺点如下：

1. 无法打字（键盘只能传输英文进去，无法使用输入法）
2. 点击速度（受限于控制方案）
3. 无法运行岛屿计划（受限于树莓派本身的性能）
4. ADB_nc 方案会导致不可知的忽然断连，需要采用 ADB 控制

## 结语

尽管方案并不完美，但足够有效。后续可能会把 ALAS 也迁移到树莓派上，彻底解放真机。
